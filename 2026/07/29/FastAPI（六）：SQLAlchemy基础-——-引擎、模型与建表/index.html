FastAPI（六）：SQLAlchemy基础 —— 引擎、模型与建表

发表于2026-07-29|更新于2026-09-28|FastAPI基础
|浏览量:

在实际开始写 CRUD 接口之前，我花了不少时间琢磨 ORM 这一层到底是怎么和 FastAPI 配合起来的。之前用过一点同步的 SQLAlchemy，但切到异步模式后，引擎创建、会话管理、模型声明的方式都有变化，为防止后面的到处碰壁，现在就把这些基础捋清楚似乎是一个更好的选择。这篇文章整理的就是这一阶段的理解，重点放在异步引擎、模型基类、字段映射、以及应用启动时自动建表这一条非常基础的链路。

在 SQLAlchemy 2.0 的异步模式下，这些操作会对应到 select()、insert() 等函数，再通过异步会话去执行。眼下我们还是先回到模型的构建上，这是所有操作的地基。

异步引擎：整个 ORM 的入口

在 FastAPI 里，我们不会每个请求都去新建一次数据库连接，而是通过一个全局的异步引擎管理连接池。create_async_engine 就是这个入口。

这里把数据库 URL 放到 .env 文件里，通过 python-dotenv 加载，避免敏感信息写死在代码中。他的格式其实也很简单“mysql+aiomysql://user:password@localhost:3306/your_database?charset=utf8”
echo=True 在开发阶段几乎是必开的，它会输出所有 SQL 语句和参数，让你清楚地看到 ORM 到底生成了什么。连接池的几个参数在生产环境里要多留意：pool_size 和 max_overflow 决定了并发能力，pool_recycle 和 pool_pre_ping 则主要解决连接超时断开的问题。

声明基类：登记所有模型

SQLAlchemy 2.0 推荐用 DeclarativeBase 作为所有模型类的父类。它的作用可以类比成“户口本”：你定义的所有表模型，只要继承了这个基类，就会被自动扫描、注册到一个叫做 metadata 的地方，后面建表、迁移都会用到。

这里我没有直接把公共字段写在 Base 里，而是等到定义具体模型时再做——但实际项目中，像 create_time、update_time 这种每个表都需要的字段，可以像下面这样抽到基类中，避免重复。

模型字段：Mapped 和 mapped_column

在 2.0 的写法里，模型字段用类型注解加上 Mapped[] 来标记。如果你只写 bookname: str，SQLAlchemy 不会把它当成数据库列，必须在前面套一层 Mapped[str]，并配合 mapped_column() 给出更细的约束。

这里有两个容易混淆的地方。一个是 func.now()，它并不是在 Python 里立刻执行，而是生成一个 SQL 表达式 NOW()，最终发给数据库去执行。另一个是默认值的几种写法：server_default 会体现在 DDL 里（DEFAULT CURRENT_TIMESTAMP），由数据库保证默认值；而如果你写了 default=func.now，那是在 ORM 层面插入数据时调用的 Python 函数。一般建议对于时间字段，直接用 server_default 和 onupdate，让数据库去维护，更加可靠。

建表的时机：利用 Lifespan 事件

表结构定义好之后，我们希望在应用启动的时候自动创建这些表（开发阶段可以这么做，生产环境更推荐迁移工具如 Alembic）。FastAPI 提供了 lifespan 上下文管理器，让我们可以在应用启动和关闭时执行异步操作。

async with async_engine.begin() 这一行做了三件事：从连接池取一个连接、开启事务、在代码块结束时自动提交或回滚。conn.run_sync() 的作用是把同步的 Base.metadata.create_all 放到线程池里执行，不阻塞事件循环。Base.metadata.create_all 会遍历所有注册过的表，生成 CREATE TABLE IF NOT EXISTS 语句，所以即使重复调用也不会报错。

当应用关闭时，lifespan 中 yield 后面的代码会执行，调用了 async_engine.dispose() 来清空连接池，确保所有连接都被正确释放。

收尾

第一，时间字段的默认值最好全扔给数据库。我一开始在代码里混用了 default=func.now 和 server_default=func.now()，结果发现直接通过数据库客户端插入数据时，create_time 并没有自动填上，因为 default 只在 ORM 层面生效。统一用 server_default 和 onupdate 能避免这种分裂。

第二，连接池参数不要完全依赖默认值。在本地开发时可能感受不到，但放到服务器上，MySQL 默认 8 小时断开空闲连接，如果不设置 pool_recycle 或者 pool_pre_ping，偶尔会出现“MySQL server has gone away”的错误，排查起来很费时间。在项目初期就把这些参数加上，是一件性价比很高的事。

这篇文章只搭好了 ORM 的骨架，下一节我会继续整理异步会话的创建方式，以及如何用它来实现上面提到的那些 INSERT、SELECT 操作。
