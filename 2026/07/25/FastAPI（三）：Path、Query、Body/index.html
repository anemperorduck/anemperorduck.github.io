FastAPI（三）：Path、Query、Body

发表于2026-07-25|更新于2026-09-28|FastAPI基础
|浏览量:

三个位置，三种工具

一个 HTTP 请求携带数据的位置主要有三个：URL 路径、查询字符串和消息体。FastAPI 为这三个位置各自配了一个函数，用来声明参数并附加校验规则。

这三个函数都来自 fastapi：

  • Path() —— 给路径参数附加校验元数据
  • Query() —— 给查询参数附加校验元数据
  • Body() —— 声明一个参数应该从请求体中获取，并可以附加校验元数据

而 Field() 来自 Pydantic，它用在 Pydantic 模型的字段上，为请求体内部的各个字段添加校验规则。

它们的本质就是“给默认值加说明书”。FastAPI 利用 Python 的类型注解和这些函数的默认值，在框架内部构建了一套校验管道，在函数体执行之前把非法请求直接拒掉。

Field() 和 Query()、Path() 的用法一脉相承，只是它在模型内部工作。... 依然表示必填，gt、max_length 这些规则同样生效。任何违反规则的请求都会在进入路由函数之前被拦截，并返回详细的 422 错误清单。

这也是 FastAPI 设计中很舒服的一点：不管参数来自路径、查询还是请求体，校验规则的声明语法是统一的。你只需要记住那一套元数据键名。

一次拦截，省下的是 Token 费用

基础讲完了，现在回到一个更贴近生产的场景。假设你在用 FastAPI 做一个 AI Agent 网关，背后接的是 LangGraph 或 LangChain，再往下才是大语言模型。用户发送一个对话请求，网关负责校验参数，然后交给下游 Agent 执行。

这种架构里，入参校验不仅是安全问题，更是成本问题。一个未通过校验的请求如果漏到下游，可能引发以下后果：

  • LangGraph 的状态机读到格式错误的 session_id，Checkpointer 无法恢复历史对话，但在抛出异常之前可能已经调用了一次 LLM 做意图识别。Token 已经花了，请求却失败了。
  • 用户把 temperature 设成了 3.0，远超出合法范围，LLM 返回的结果混乱，后续的工具调用链也全跑偏了。如果入口校验就能拦住，后面的一系列浪费都不会发生。
  • Prompt 超长但未做限制，一次请求消耗数万 Token，加上高并发，月账单会非常难看。

在网关层用 FastAPI 的声明式校验，拒绝这些非法请求的成本几乎为零。框架在 C 扩展层面（Pydantic v2 的 Rust 内核）就完成了所有检查，Python 业务代码一行都没有执行。换句话说，凡是能进到路由函数体的参数，都是干净的。这个保证让下游 Agent 可以专注于业务逻辑，不必在每个节点都写一堆判断。

校验通过之后：参数如何交给 LangGraph

校验完成后，路由函数里的参数都是干净、合法、类型正确的 Python 对象。这时你可以放心地把它们组装成 Agent 的初始状态：

  • str(session_id) 作为 LangGraph 的 thread_id，交给 Checkpointer 恢复历史状态。
  • temperature 和 max_tokens 作为运行时配置，传递给 LLM 调用节点。
  • body.prompt 和 body.history 变成图状态中的 current_prompt 和 chat_history。

整个过程的分工很清楚：FastAPI 管“数据能不能用”，LangGraph 管“数据往哪走”。这种分层让每一层都可以独立测试，Agent 内部也不用再为校验分心。

几个容易踩到的小坑

1. 版本变更中的细节

现在 FastAPI 与 Pydantic v2 深度绑定。如果你翻到一些旧教程，可能会看到 regex 参数和 schema_extra，它们在 v2 中已经变成了 pattern 和 json_schema_extra（或者直接使用 examples 列表）。这些变更不会导致程序报错（有兼容层），但如果在团队里形成惯性，迁移到纯 v2 环境时会踩坑。

2. 资源初始化不要放在路由函数里

有些同学习惯在路由函数内部创建 LLM 客户端或数据库连接。每次请求都新建连接，并发一高，文件描述符和内存就上去了。利用 FastAPI 的 lifespan 上下文管理器，在服务启动时初始化全局资源，关闭时释放，每个请求通过 request.app.state 或依赖注入来拿。

3. 异步路由里别用同步 I/O

声明为 async def 的路由，所有可能等待的操作都要用 await。如果 LLM SDK 只提供同步版本，可以用 run_in_threadpool 把它隔离到线程池，避免阻塞整个事件循环。

FastAPI 的参数声明系统学起来很快，但把它用好，需要你在设计接口时就把“什么不该进来”想清楚。Path 让路径参数从字符串变成强约束的资源标识，Query 把行为控制参数的可选范围锁死，Body 和 Field 则把 JSON 载荷的边界写在了代码里而不是文档里。对于 AI Agent 网关这种每一次请求都可能触发 Token 消费的场景，这层入口校验就是最早的止损点——拒绝一个非法请求，有时比处理它更有价值。
