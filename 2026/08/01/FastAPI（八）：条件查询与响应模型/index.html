FastAPI（八）：条件查询与响应模型

发表于2026-08-01|更新于2026-09-28|FastAPI基础
|浏览量:

上一节我们利用依赖注入拿到了异步数据库会话，完成了一个最朴素的全表查询：select(Book)，然后直接把 ORM 对象列表丢给 FastAPI 去序列化。这作为起步没问题，但真实接口很少这么“佛系”——前端通常会传一堆可选的筛选参数，后端也必须对返回字段做精确控制。这一节就把这两件事串起来，顺便梳理在这个过程中容易弄混的几个概念。

代码

在展示具体分析之前，先把今天最终落地的代码完整放出来。它承袭了前两节的异步引擎和模型定义，新增了动态条件查询、Pydantic 响应模型以及辅助函数。你可以直接复制到一个 main.py 中跑起来，数据库配置沿用项目根目录的 .env 文件。

以上代码就是今天完整的骨架。接下去把其中几个设计点拆开说清楚。

为什么用 Pydantic 模型而不是裸返回 ORM 对象

上一节为了方便，直接在路由里 return books，把 Book 对象列表交给了 FastAPI 自带的序列化机制。这种方式在简单场景下能跑，但存在几个硬伤：

  • 数据库表的所有字段（包括 create_time、update_time）会被无差别暴露。
  • 无法添加业务层面的额外字段，比如本次我们希望区分数据是来自“简单查询”还是“条件查询”，就需要一个 source 标记。
  • 字段命名、顺序完全由数据库表决定，前端耦合度过高。

因此引入了 BookOut 这个 Pydantic 模型。它明确声明了接口要返回哪些字段，以及 source 的字面量约束。至于从 Book 对象到 BookOut 的转换，没有使用 from_attributes=True 自动映射，而是写了一个辅助函数 make_book_out。原因在于 source 并不存在于 ORM 对象中，如果开启 from_attributes，Pydantic 在校验时会因为找不到该字段而报错。显式构造虽然多敲了几行代码，但语义非常清晰，也不容易出现隐式行为带来的意外。

这里有三个容易忽视的细节。

第一，Book.bookname.like(...) 不会触发数据库查询。 Book.bookname 是 SQLAlchemy 的列描述符，like() 或者 == 操作只是构建了一个 BinaryExpression 对象，里面存储了列、运算符和参数占位符。真正的 SQL 要到 db.execute() 时才发送到数据库。理解这一点很重要，否则容易误以为在循环里拼条件会有性能开销。

第二，where(*conditions) 的展开逻辑。 当 conditions 非空时，多个条件会被 SQLAlchemy 默认用 AND 连接。比如传入 author=曹雪芹&price=59.9，最终生成的 SQL 会是：

第三，当 conditions 为空列表时，where() 不接收任何参数，相当于不带 WHERE 子句，查询返回全表数据。 这正是“不传任何参数时返回全部记录”这一需求的实现方式，不需要额外写分支逻辑。

用 echo=True 观察控制台输出的 SQL，对理解这几个行为非常有帮助。推荐在开发阶段一直开着，它是学习 ORM 最直接的窗口。

查询结果取值：几种方法的使用边界

在几个接口里分别用到了 scalars().all()、scalar_one_or_none() 和 db.get()。这三种方式适用于不同场景，用错的话要么拿不到数据，要么报异常。

  • result.scalars().all() 返回 list[Book]，适合多行结果。如果没有任何匹配行，返回的是空列表 []，而不是 None，所以判空要用 if not books:。
  • result.scalar_one_or_none() 严格要求结果集最多只有一行。如果多于一行会抛出 MultipleResultsFound；如果零行则返回 None。用在主键唯一查询中非常合适，可以尽早暴露数据问题。
  • await db.get(Book, primary_key_value) 是按主键查询的快捷方式，内部会先检查身份映射缓存，没命中再发 SQL。需要注意它的第二个参数只能传主键值，不能像 .where() 那样使用其他列条件。如果传了非主键关键字，会直接得到 TypeError。

另外，Result 对象是一次性游标。如果你对同一个 result 先调用了 scalars().all() 再调 scalars().first()，后者会返回 None——因为游标已经遍历完了。每个查询应该独立执行，不要复用已经消费过的 Result。

参数校验与文档生成

查询参数上加了 Query() 装饰器，比如 price: float | None = Query(default=None, ge=0)。它做了三件事：

  1. 让参数变为可选，缺省为 None；
  2. 在 OpenAPI 文档中生成 description；
  3. 如果调用方传了负数价格，FastAPI 会在进入路由函数之前直接返回 422 校验错误，不需要在业务代码里手动判断。

类型注解 str | None 和默认值 = None 共同表达了“可选”的语义。判断用户是否传了这个参数，我习惯用 if price is not None，因为这种写法能准确区分“没传”和“传了零值”这两种情况——如果用 if price: 的话，价格为 0 的合法请求就会被误判为未传。
